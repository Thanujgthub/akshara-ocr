## Recovery format and limits

`full/checkpoints/step-NNNNNNN[-version]/` contains `adapter/`, `state.pt`, `recovery.json`, `checksums.json` and a separate write-timing record. Existing compatible state keys are retained: optimizer, LambdaLR scheduler, epoch, next shuffled index, updates, elapsed time, best-validation record, Python/Torch CPU/CUDA/augmentation RNG. New checkpoints also record NumPy RNG, actual precision, image/label/group fingerprint, effective batch4 and accumulation progress0. BF16 does not use a GradScaler; its saved value is explicitly null. FP16 is not implemented. Legacy checkpoints without new fingerprints are not equivalent evidence of verified transfer and must not silently be promoted to this cloud lineage.

Writes stage under `.incomplete-*`, hash/verify all recovery files, rename to a new immutable version, then atomically update `resume.json`. Earlier checkpoints/epoch adapters remain intact. Recovery checks signature and checksum index, falls back to the highest valid compatible checkpoint, and preserves a replaced pointer. Missing/corrupt pointer recovery requires the expected training signature. The deterministic epoch permutation is reconstructed from the frozen manifest ordering and seed; checkpoints occur only at optimizer boundaries. After a crash, uncheckpointed microbatches may be repeated. Lost work is bounded by the last **durably synchronized** checkpoint, not just the local125-update cadence.

Epoch inference exports commit separately with checksums; `best.json` records validation choice. `selection.json` is locked before final testing. The selected export is separate from latest resumable state and historical pilot artifacts. No optimizer-state resume is claimed when initializing from the pilot's adapter-only export: this is a named new experiment with a new optimizer/scheduler.

Drive snapshots are append-only `runs/<run>/snapshot-*` directories containing recovery checkpoints, manifests/configuration, logs, validation outputs and any authorized final outputs. Each has a checksum index; the latest pointer is written only after verification. Concurrent checkpoint advancement causes a snapshot retry rather than mixing its pointer and weights. Partial JSONL tails are excluded from snapshots. Restore scans intact snapshots newest first and requires an empty local run directory. Earlier snapshots are retained for corruption fallback. Verify Drive storage headroom; snapshots consume additional quota. A mounted filesystem cannot provide an absolute distributed-lock/durability guarantee: one-runtime ownership and user confirmation remain essential.

The controller requests a safe stop after a configurable three-hour operational budget, or via the local `STOP` sentinel. It waits for an optimizer/prediction boundary and synchronizes. A service disconnect may happen sooner. To resume: authorize the new runtime, confirm the old one is gone, stage identical inputs, restore the newest intact snapshot, retain the **same run name/config/precision**, explicitly remove only the local STOP sentinel, and launch once. Do not delete checkpoints or reset to the original model on a resume failure. An active process lock rejects a duplicate launch in one runtime; the manual Drive lease prevents unintended cross-runtime duplication.

## Accuracy and interface next steps

Keep literal transcription separate from contextual suggestions. The present word-crop model has no validated sentence-context correction stage; it must flag unreadable/uncertain words rather than invent them. Prioritize human review of validation errors, short words, vowel signs, numerals, contamination and repetitions. Only evidence-backed label corrections and validation-supported changes should feed a later controlled experiment. More word presentations alone do not guarantee99%.

The existing studio should show the active model/version, training versus inference availability, clear word-crop scope, side-by-side crop/raw text, uncertainty reasons, editable user corrections, and export provenance. None of these should imply calibrated confidence or silently alter Telugu spelling/digits.
